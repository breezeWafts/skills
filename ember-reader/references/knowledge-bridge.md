# 知识库融合规则 · 辅助阅读解构参照

本文件规定 `ember-reader` 如何把内置的五领域知识库用作**辅助解构理解的参照**。它服务于「把书拆得更清楚」，不改变四级渐进交互协议，也不改变任何一层的内容纯度。

## 一、定位与边界

**内置资产**：`knowledge/` 下 5 个领域库 + `README.md` + `index.json`，共约 4741 行、506 个可索引章节。来源为用户整理的电子书、网页教程、文档与代码片段，已提炼为规则、定义、算法、规范与检查清单，不收录示例、故事与轶事；来源与限制见 `knowledge/README.md`。

| 知识库是 | 知识库不是 |
|---|---|
| 概念定义与判定标准 | 书籍原文或章节摘要 |
| 可执行规则、流程框架、检查清单 | 例证、故事、类比（这些只能来自书中） |
| 反模式与失败信号 | 对书观点的权威裁决 |
| 同领域的结构化参照系 | 联网检索得到的外部同类资料 |

**三条硬边界**
1. **不冒充**：知识库内容一律标注 `〔知识库·…〕`，与书中原意分开呈现，绝不写进「原文内容」栏。
2. **不倾倒**：禁止把整库或整章载入上下文；按章节精确取片段，单次不超过 6000 字符。
3. **不越权**：知识库命中不改变覆盖度声明，不替代 L4 的联网检索，不替用户判断理解程度。

## 二、领域判定（Step 3.5 执行）

| id | 库文件 | 典型书 | 使用入口 |
|---|---|---|---|
| `it` | `IT类.md` | 架构设计、系统运维、安全合规、等保、UI/UX、无障碍 | 方案评审用第一篇，上线用第二篇检查清单，安全用第三篇，界面走查用第四篇 |
| `data` | `数据分析类.md` | 数据分析、统计实验、指标体系、建模、可视化、数据治理 | 先定决策与口径，再按章取方法，收尾用流程清单验收 |
| `aesthetics` | `美学艺术类.md` | 美学原理、设计方法、艺术史、配色版式、创作评审 | 立意用第一篇，选形式用第二篇，流程与评审用第三篇 |
| `photography` | `摄影类.md` | 摄影表达、布光、构图摆姿、后期交付 | 拍摄前查第 2~7 章，组图查第 8 章，后期交付查第 9~10 章 |
| `film` | `影视类.md` | 影视创作、剧本、分镜、剪辑声音、短视频 | 开发期用剧本章，筹备期用分镜章，后期用调度与剪辑章 |

**判定流程**
1. 依据**书名 + 目录 + 已获取摘要**判定主领域；运行 `python scripts/knowledge.py domains` 查看路由关键词。
2. 可多领域命中：取主库，次库仅用于补概念定义，避免参照过载。
3. 关键词不用缩写硬套：书中说「等保」、库里写「网络安全等级保护」时，用 `query` 的同义扩展或直接换词；必要时先 `sections --domain <id>` 浏览章节树再定检索词。
4. **未命中**（文学、历史、心理、传记等）→ 明确记录「知识库未命中」，后续四级一律不引入知识库，禁止硬套规则。
5. 命中结论与理由写入材料清单，随首次输出一并声明「本书命中 X 知识库，作为辅助参照」。

## 三、K 参照卡片（内容池旁路条目）

检索结果整理为 K 卡片，**不占展示层级、不单独成级**，只挂在对应 L1 主干编号下。

| 字段 | 说明 |
|---|---|
| `id` | `K1`、`K2`… 按书编号 |
| `domain` / `file` | 领域 id 与库文件名 |
| `path` / `lines` | 章节路径与 `L起–L止`，用于可追溯标注 |
| `excerpt` | 该章节的关键条目（转述或短引），不整章复制 |
| `role` | 定义锚点 / 规则校准 / 检查清单 / 反模式 / 流程框架（五选一） |
| `l1_ref` | 挂载的 L1 主干编号；无法挂载则标记「全书级」 |
| `note` | 适用条件、版本时效或与书中表述的差异 |

**约束**：每本默认 3–8 张；同一 L1 主干下不超过 3 张；单次检索 `--top 5 --max-chars 6000`；片段被截断时按行号回查原文，不脑补缺失部分。

## 四、四级渐进流程中的用法

| 层级 | 用法 | 输出约束 |
|---|---|---|
| **L1 主干** | 只用 K 卡片做**内部自检**：主干命题是否覆盖了该领域的核心维度、有无把规则误写成主张。 | **不输出任何知识库内容**，不提前剧透下一层；L1 仍须零修饰、零例证。 |
| **L2 修饰·知识点** | 每个知识点块的三栏式笔记之后，另附「〔知识库参照〕」条目：给出该概念在库中的定义、适用条件、边界或检查项。 | 单独成条，与「内容」栏物理分离；标注 `〔知识库·文件｜章节｜行号〕`。 |
| **L3 例证·故事·类比** | 把书中例证映射到 K 卡片的对应规则或「失败信号」，形成「例证 ↔ 规则」对照，说明这个例子究竟在证明什么。 | 例证本身仍只取书中内容；映射是参照，不新增书中没有的故事。 |
| **L4 同类对照** | 四栏（共识/分歧/补充/反例）之后增加「**知识库校准**」小节：指出哪些结论在本地库中有对应规则、检查项或反模式。 | 联网资料与知识库并列为两类来源，各自标注；二者冲突时并列呈现、不擅自裁决。 |
| **Step 6 方案** | 用库中的流程清单／检查清单生成复习验收项（标注来源），作为费曼自检与一页纸复盘的补充。 | 不替代读后四问；不把行业规范写成用户的必做动作。 |
| **Step 7 导出** | 经授权后，可在精简知识库末尾附「知识库参照索引」（文件 · 章节 · 行号）。 | 索引单独成节，不与书籍条目混排。 |

## 五、来源标注与冲突处理

**统一标注格式**：`〔知识库·IT类.md｜第三篇 / 7.1 上线前安全检查清单｜L1367–1375〕`。多张卡片连续出现时，每条各自标注，不用「同上」。

**冲突处理**
- 书中原意与知识库规则不一致时，**并列呈现并各自标注来源**，说明差异点（年代、适用条件、流派、版本），不替作者或库裁决。
- 知识库中的法规、标准与平台规范以撰写时有效版本为准，实施前须复核最新版本；OCR 文本可能有错别字，引用具体数值前回查原书。
- 库内 `[cite:N]` 引文标记保持原样，不改写、不当作本书出处。
- 知识库只覆盖五个领域，命中不等于「已读完该领域全部资料」，不得据此夸大覆盖度。

## 六、检索工具用法（渐进披露）

```
python scripts/knowledge.py index                       # 重建 knowledge/index.json
python scripts/knowledge.py domains                    # 五个领域与路由关键词
python scripts/knowledge.py sections --domain it        # 浏览某库章节树（含行号）
python scripts/knowledge.py query "等保 上线检查" --domain it --top 5 --max-chars 6000
python scripts/knowledge.py query "构图 光比" --json    # 结构化结果，便于程序解析
python scripts/knowledge.py sync --from "E:/skills/material/knowledge/dist"
```

- `query` 返回**带出处的最小片段**：文件 · 章节路径 · 行号区间 · 相关度；默认做同义扩展（`--no-expand` 可关闭）。
- 无命中时先 `sections` 浏览目录再换词，**不得**用「随便取一段」凑数。
- `sync` 会把源目录 `*.md` 复制进包并重建索引；知识库更新后须重跑 `index`，否则行号会失效。

## 七、自检清单（每次融合后逐条核对）

- [ ] 领域判定有依据（书名/目录/摘要），未命中已明确记录
- [ ] 所有 K 卡片带文件 · 章节 · 行号，且未冒充书中原意
- [ ] L1 未出现任何知识库内容
- [ ] 单次载入 ≤6000 字符，卡片数 3–8 张
- [ ] 冲突并列呈现、未擅自裁决；法规/数值已提示复核
- [ ] 覆盖度声明未因知识库命中而改变
- [ ] L4 仍完成了联网同类检索，未以知识库替代
