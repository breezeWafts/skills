# 配套图标系统 · 一干生六相 · v1.2.0

依据 `/evan-design` 的 L0 六步创作法与八意识联检，为主图标「剥枝见干」设计同风格的配套图标组。立意档案见 `references/icon-design.md`。**v1.2.0 起整套改用白瓷片 app-icon 语言：白色 squircle 容器 + 深蓝灰极简线稿 + 大留白，画面内 0 个文本节点。**

## 一、美学立意（L0）

**一句话境界：一干生六相。** 同一根主干，因读者处在不同的理解阶段而显出六种形态——不是六个功能按钮，而是同一条路径上的六个刻度。观者感到的是「还在往上走」，而非「这里有很多功能」。

- **主范畴：优美**（与主图标一致）；**次范畴：意境**（同一物象的六种显相，虚实相生、以少总多）。
- **未采纳**：崇高（尺度压迫）、喜剧/荒诞（范畴错配）、彩色分级（用红蓝绿区分 L1–L4 既违反「不单靠颜色传达信息」，又造成焦点泛滥与审美疲劳）。
- **价值观校验**：六级渐进、看懂就停，不催促、不炫技，与技能的交互伦理一致。

## 二、美感机制

| 机制 | 转译 |
|---|---|
| 格式塔同构 | 分叉数量、长度与末端形态直接对应各级信息量：L1 零分叉 → L2 两对短枝 + 四个方点 → L3 一对长枝 + 两张故事卡 → L4 三干并立 + 虚线互证。力的结构由「收束」走向「展开」。 |
| 升华与暗示（秘） | 全套不写数字、不写字、不用颜色分级；层级靠形态差异让观者自己补全，呼应技能的信息渐进披露。 |
| 心理距离 | 统一的白色 squircle 把主视觉框出，图形四周大留白，与相邻内容保持观照距离。 |

**意境四步**：立意「一干生六相」→ 择象「书 + 主干」（六枚共用同一物象，禁另起炉灶）→ 布虚「单一骨架 + 大留白」→ 留余「顶端收笔不封口」。

## 三、v1.2.0 形式落地

| 层 | 决策 |
|---|---|
| L1 · 微 | 线稿 `stroke-width:1.5`、圆端点；尺寸档 34 / 21 / 16px |
| L1 · 并 | 单套 Token 在根部定义一次；六枚共用同一容器与同一段书脊基线 `M21 47 H43`；三版主图标路径完全一致 |
| L1 · 间 | 图形集中在中心约 30×30 单位，留白 ≥40%；容器边界仅 `rgba(28,28,28,0.06)` 1px |
| L1 · 秘 | 每枚焦点 ≤1；信息渐进，不标数字 |
| L1 · 素 | 靛蓝灰 `#526883`（S≈23%），无渐变、无高光、无纯白纯黑、**无文字** |
| L1 · 气 | 独立小尺寸资产不叠阴影噪点 |
| **L1 · 破** | **配套组 0 破格**。主图标右上朱砂点是全系统唯一破格，若每枚再点朱砂即成焦点泛滥；零破格合规，且反过来让主图标更可辨。 |
| L2 · 秩序 | 中轴对称保证 34px 可辨；卡片内居中，内边距取斐波那契 34px 模数 |
| L3 · 感知 | 暗色由宿主覆盖 Token 实现（墨底 `#24262A` / `#708CB1`），非简单反色 |
| 技术例外 | 容器 `rx=20` 写字面值：SVG 1.1 几何属性中的 `var()` 在 Chromium 不解析，实测会退化为直角。详见 `icon-design.md` 第三节。 |

## 四、审美自检

- **质**：去掉「标识四个阅读层级」的用途，六枚仍是同一株植物的六种生长瞬间，形式自足。
- **量**：无需说明即可直觉感知「从一根到很多根」，气质不靠术语传达。
- **关系**：共用书脊本为秩序统一，恰好对应「所有层级都挂在同一条 L1 主干上」的数据模型，无目的而合目的。
- **情状**：换成通用「数字徽章 / 彩色标签 / 齿轮灯泡」就不像本技能。
- **进阶**：养眼（低饱和、统一线宽）→ 养心（生长节奏带来代入）→ 养神（一干六相、境生象外）。
- **三赛道**：功能（六级语义可辨、三档尺寸、sprite 可内联）／审美（范畴一致、焦点 ≤1、0 破格）／价值（不靠颜色单独编码、色觉障碍友好、不制造速成焦虑）。

**速查表核对**：留白 ≥40% ✅｜斐波那契间距 ✅｜无字号与字体族（纯图形）✅｜图形对比 ≥3:1（≈5.2:1）✅｜不单靠颜色（形态冗余编码）✅｜饱和度 ≤45% ✅｜焦点 ≤1/枚 ✅｜无纯白纯黑 ✅｜渐变 0 ✅｜Token 驱动 ✅｜破格 0 处 ✅｜无自动动效 ✅｜`<title>`/`<desc>` 可读名称 ✅｜**画面内文字 0** ✅。

| `assets/icons/export.svg` | 授权导出 · 知识框 + 向右箭头 | `ember-reader-export` |
| `assets/icons/sprite.svg` | 六枚合并（仅 `<defs>`，需内联使用） | — |

**复用约定**
- 独立 SVG 可直接 `<img>` 引用；Token 定义在根部 `style`，不依赖宿主样式表。
- 批量使用：把 `sprite.svg` 内联进页面，再 `<svg viewBox="0 0 64 64"><use href="#ember-reader-l1"/></svg>`；跨文件 `<use href="icons/sprite.svg#…">` 部分环境受限，优先内联。
- 暗色：覆盖根节点 `--icon-bg:#24262A; --icon-ink:#708CB1; --icon-cut:#24262A; --icon-edge:rgba(255,255,255,0.08)`；**不要**给配套图标新增朱砂点。
- **禁止在图标内添加任何文字、字标、数字、字母**，也禁止渐变、第二处强调色或额外装饰；层级语义一律由分叉形态承担。旧 `brand-lockup.svg` 含中英文字标，v1.2.0 已移除。
- 重新生成：`python scripts/build_icons.py`，脚本输出 12 个 SVG 并自检 XML 与「无 `<text>` 节点」。

## 六、PNG 位图资产（v1.4.0 新增，供平台上传）

SVG 用于界面内联；平台上传、favicon、应用商店等场景需要位图，统一放在 `assets/png/`。**几何与配色完全继承 SVG，无任何新增文字或装饰**，只是把矢量在目标尺寸原生栅格化。

| 命名 | 尺寸 | 典型用途 |
|---|---|---|
| `ember-reader-16/32/48.png` | 16 / 32 / 48 px | favicon、标签页、托盘小图标 |
| `ember-reader-64.png` | 64 px | 列表缩略图、UI 内联 |
| `ember-reader-128.png` | 128 px | 技能市场、扩展程序常用规格 |
| `ember-reader-180.png` | 180 px | Apple touch icon |
| `ember-reader-192.png` / `ember-reader-256.png` | 192 / 256 px | PWA、桌面快捷方式 |
| `ember-reader-512.png` | 512 px | 主上传件、应用商店大图 |
| `ember-reader-512-opaque.png` | 512 px | 不接受透明通道的平台（暖白底压平，无 alpha） |
| `ember-reader-dark-512.png` / `-mono-512.png` / `-card-512.png` | 512 px | 暗色主题、单色印刷、深色卡片展示 |
| `level-1…4 / study-plan / export` 各自 `-64.png` / `-256.png` | 64 / 256 px | 四级交互与方案、导出环节的配图 |
| `favicon.ico` | 16 + 32 + 48 px | 站点 favicon，多尺寸合一 |
| `preview.png` | 848 × 344 px | 十枚图标总览（深色底、零文字），仅作预览 |

**栅格化约定**
- 所有 PNG 为 RGBA，四角保持真实透明；仅 `-opaque` 与 `preview.png` 为无 alpha 的 RGB。
- 每个尺寸独立按目标像素渲染，禁止把小图放大充当大图；`16px` 若被合成器丢弃，脚本会从 64px 做 Lanczos 降采样兜底。
- 生成命令：`python scripts/build_icons_png.py`（默认写 `assets/png/`，可用 `--outdir` 改路径，`--browser` 指定浏览器）。依赖本机 Chromium 系列浏览器与 Pillow；**不用 cairosvg**——它不解析根节点 `style` 里的 CSS 自定义属性，且 Windows 常缺 libcairo DLL。
- 脚本逐张自检：尺寸、alpha 边界（`getbbox()` 宽度/高度 ≥ 93%，防止无头浏览器视口截断）、不透明占比 ≥ 25%、浅/暗/单色/卡片四版的关键色是否存在。
- 上传前建议用 `preview.png` 核对整套一致性；平台若强制纯色背景，直接用 `ember-reader-512-opaque.png`。
